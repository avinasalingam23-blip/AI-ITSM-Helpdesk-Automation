# VPN connection and authentication

Scope: employees who cannot connect to the corporate VPN, including authentication failures. Owner: Network Support. Approved demo article, reviewed 2 November 2026.

First check whether the laptop can reach an ordinary web page. Confirm the date and time are correct, because an incorrect clock can prevent authentication. Open the company-approved VPN client and verify that the corporate profile is selected. Disconnect an existing VPN session and reconnect once. Complete the normal multi-factor authentication prompt on your enrolled device; never share the code with the helpdesk.

If authentication fails, check whether the account password has expired or the account is locked. Use the approved identity recovery flow rather than repeating sign-in attempts. If an error persists, capture the error text, time of failure and client version. Do not include passwords, recovery codes or tokens in a ticket. Avoid disabling endpoint protection or changing VPN server settings.

A VPN connection incident affecting one employee has high urgency, individual impact, priority P2 and assignment group Network Support in this prototype. A team-wide outage with high urgency is P1. A ticket remains open until an agent or a verified workflow confirms recovery. There is no approved automatic VPN repair in this demo. Network Support investigates persistent failures.
